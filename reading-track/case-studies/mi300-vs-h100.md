# Case Study — AMD MI300X vs NVIDIA H100

> Sources: AMD MI300X launch materials; SemiAnalysis and Chips and Cheese comparative analyses.

The MI300X is AMD's H100-class accelerator. The comparison is instructive because it exposes which axes vendors compete on — and which the software stack hides.

## The headline specs (approximate, at launch)

| | H100 SXM5 | MI300X |
|---|---|---|
| HBM | 80 GB HBM3 | 192 GB HBM3 |
| HBM bandwidth | 3.35 TB/s | 5.3 TB/s |
| BF16 tensor TFLOPS (dense) | 989 | ~1300 |
| FP8 tensor TFLOPS (dense) | 1979 | ~2600 |
| TDP | 700 W | 750 W |
| Interconnect | NVLink 4 + InfiniBand | Infinity Fabric (intra-platform) + InfiniBand |

On paper, MI300X has **more memory, more bandwidth, more raw FLOPS** than H100. It's also notably more expensive in some configurations.

So why isn't MI300X the dominant choice?

---

## The software gap

The single most cited reason is software. Reading any AMD vs NVIDIA comparison, watch for these:

- **ROCm vs CUDA.** ROCm is AMD's CUDA equivalent. It has been improving rapidly but still lags on:
  - PyTorch nightly-feature parity (Triton support, FSDP edge cases, etc.).
  - vLLM / SGLang first-class support.
  - Custom kernel ecosystem (FlashAttention forks, CUTLASS-equivalent ASCBLAS/RCCL maturity).
- **HIP.** AMD's CUDA-source-compatible C++ API. Many kernels translate; not all do.
- **Tooling.** Profilers, debuggers, and ecosystem libraries are less polished.

The result: MI300X can be 30–50% faster than H100 *on paper* and slower in practice because the kernels aren't tuned for it.

This gap is closing, but unevenly. Some workloads (large dense inference, where AMD has invested) are at parity; others (training with mixed precision and aggressive overlap) still lag.

## What the press is really comparing

When you read an MI300 vs H100 article, identify which of these axes the analyst is making the claim on:

1. **Theoretical peak.** AMD usually wins. This is the *least* important number for real workloads.
2. **Memory capacity.** MI300X's 192 GB is a real win — fewer GPUs needed for a 70B-class model.
3. **Memory bandwidth.** AMD wins here too; matters for decode-heavy inference.
4. **Sustained inference throughput at a fixed model + batch.** Depends on whether the kernels are tuned. Mixed results.
5. **Training throughput.** Generally NVIDIA wins due to FSDP / Megatron / NCCL maturity.
6. **$/token at scale.** Highly cloud-specific; MI300X is rented at lower hourly rates by some clouds.
7. **Availability.** Sometimes the real comparison — getting H100s has been hard, MI300X may be more available.

A well-written comparison will state which axis (or axes) it's evaluating. A poorly-written one will conflate them.

## The MI300A / MI300X / MI325X / MI350 progression

For tracking AMD's roadmap:

- **MI300A** (2023): CPU+GPU on package (APU). Niche for HPC.
- **MI300X** (2023): pure GPU. H100 competitor.
- **MI325X** (2024): refresh, more HBM, modest improvements.
- **MI350 / MI355** (2025): next generation, with new tensor format support.
- **MI400 series** (~2026): future.

When an analyst writes about "the AMD roadmap," it's roughly this sequence.
